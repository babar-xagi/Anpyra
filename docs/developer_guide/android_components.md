# 🧩 Android Components and Code Ownership

The current source checkout focuses on Android. `common/`, `platforms/`, desktop/iOS placeholders and registry dispatch have been removed. Public application imports and the Android build pipeline remain compatible. This cleanup ships in 0.1.1; immutable 0.1.0 retains its original internal layout.

## 🗺️ Find the implementation

All paths below are under `src/anpyra/`.

| Component | File | Main responsibility |
| --- | --- | --- |
| Authoring API | `api.py` | Activity/TextView editor signatures and host-execution errors |
| Project configuration | `config.py` | AppConfig, Project, TOML and safe paths |
| Starter project | `scaffold.py` | app.py/config/ignore templates |
| Command interface | `cli.py` | Arguments, check/build/verify/adb dispatch |
| Build pipeline | `build.py` | Stage ordering, identity, report and output publication |
| Python analysis | `compiler/frontend.py` | AST validation, types, symbols and lowering |
| Intermediate operations | `compiler/ir.py` | App/function/operation records |
| Native screen calls | `android/screen.py` | Android Activity/TextView descriptors, methods and UI operation emission |
| Method generation | `android/codegen.py` | Register frames, scalar/helper/control-flow emission and constructor/lifecycle code |
| Dalvik assembly | `android/dalvik.py` | Opcodes, instruction encoding and branch labels |
| DEX data records | `android/dex_types.py` | Method/prototype keys and result/listing dataclasses |
| Binary helpers | `android/encoding.py` | Alignment, ULEB128, modified UTF-8 and string ordering |
| DEX file | `android/dex.py` | Pools/indexes, section layout, class data and checksums |
| Manifest writing | `android/manifest.py` | Binary AndroidManifest.xml |
| Manifest reading | `android/manifest_inspect.py` | Generated manifest profile parsing |
| Unsigned APK | `android/packaging.py` | Deterministic two-entry ZIP |
| Signing identity/APK v2 | `android/signing.py` | Retained key/certificate and signature block |
| Integrity inspection | `android/verify.py` | Signature/content/manifest/DEX verification |

The [source reference](source_reference.md) details each file's functions and tests. `android/dex.py` is the sole DEX implementation; there is no forwarding compiler/dex.py file.

## 📺 How a screen is produced

1. `api.py` defines authoring method signatures; its bodies do not implement a host UI.
2. `frontend.py` validates `TextView(self)`, `set_text` and `set_content_view`, then creates IR.
3. `screen.py` owns Android UI descriptors and method references. `emit_screen_operation` emits lifecycle-super, widget construction, text and attachment calls into an assembler.
4. `codegen.py` assigns registers, delegates UI operations to screen.py, and assembles method code.
5. `dex.py` collects/indexes references and packages that code into DEX; Android executes it and renders the native views.

No software screen renderer, preview window, layout engine, Button or callback is implemented in this version. The code generates Android's native calls.

## 🛠️ Where to fix a bug

| Symptom | Begin here |
| --- | --- |
| Source rejected or accepted incorrectly | frontend.py → IR contract |
| Wrong widget/context/text receiver | screen.py → register map in codegen.py |
| Wrong helper argument/result or branch | codegen.py → dalvik.py |
| Correct listing, malformed DEX | dex.py → encoding.py |
| Wrong package/SDK/launcher metadata | config.py → manifest.py |
| Wrong APK entries/timestamps | packaging.py |
| Update fails due to identity | signing.py and retained project state |
| Verification rejects generated bytes | verify.py/manifest_inspect.py and the matching writer |
| Wrong path/adb arguments | cli.py and project-relative config |

## 🤝 Contributor workflow

Implement one observable behavior across the required components. Adding a new widget method can require authoring signatures, front-end checks, IR records, screen method references/emission and tests. The DEX writer derives reference types/prototypes from registered screen/helper methods, but it does not invent unsupported source or UI behavior.

Keep generated artifacts and signing files out of the source package. Preserve immutable historical fixtures. Use tests that inspect actual bytes/behavior, then follow [device testing](testing.md). The cleanup has exact DEX regression hashes and same-identity APK comparisons; do not casually update those baselines to hide an output change.

The current priority is to finish Android validation, then language/register improvements, layouts, events/state, modules/resources and release identity. Other platforms are deferred.
