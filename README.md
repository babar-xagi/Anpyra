# Anpyra

Anpyra compiles a small, typed subset of Python directly into Android DEX bytecode and a signed APK. Version **0.1.0** turns the successful PyAndroid experiments 001–008 into one installable framework, using experiment 008 as the compiler foundation.

The build pipeline is written in Python: AST analysis, typed IR, register allocation, Dalvik instructions, DEX writing, binary Android manifest, APK packaging, and APK Signature Scheme v2 signing. Building does not require Gradle, Java, Kotlin, D8, R8, AAPT2, or apksigner. The host dependency is `cryptography`. Android's ART executes the resulting bytecode; application source is parsed and never executed on your computer.

This is an **alpha framework for small native apps**. It supports the language and UI features demonstrated by the experiments; it does not yet implement general Python or the full Android API.

## Start here

Use Python 3.11 or newer. From this repository:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
anpyra doctor
anpyra build examples/hello
anpyra verify examples/hello/build/dev.anpyra.hello.apk
```

On Linux/macOS, activate the environment with `source .venv/bin/activate`.

Create your own application:

```powershell
anpyra init myapp --package dev.example.myapp --label "My App"
anpyra check myapp
anpyra build myapp
```

The signed APK is `myapp/build/dev.example.myapp.apk`. You can copy it to an Android device and install it. With optional Android platform-tools on `PATH` and a connected device:

```powershell
anpyra install myapp/build/dev.example.myapp.apk --launch
# Select a device when more than one is connected:
anpyra install myapp/build/dev.example.myapp.apk --serial DEVICE_ID
```

You can also use `python -m anpyra` in place of `anpyra` for every command.

## Write an app

```python
from anpyra import Activity, TextView


class MainActivity(Activity):
    def on_create(self, state):
        title = TextView(self)
        title.set_text("Hello from Anpyra!")
        self.set_content_view(title)
```

These authoring classes provide editor-facing Python types. The compiler maps them to `android.app.Activity` and `android.widget.TextView`. Run the generated APK on Android; running `app.py` on the host is not an app preview.

The [score example](examples/score/app.py) also demonstrates typed functions, arithmetic, and conditional UI calls.

## Configure a project

Each application has an `anpyra.toml` file:

```toml
[app]
package = "dev.example.myapp"
label = "My App"
entry = "app.py"
version_code = 1
version_name = "0.1.0"
min_sdk = 24
target_sdk = 36
output_dir = "build"
```

Paths resolve relative to this file, so `anpyra build path/to/myapp` works from another directory. Settings are validated; misspelled keys, invalid types, escaping paths, and overlapping source/output/signing directories fail before building.

The default target SDK preserves the experiments' API 36 setting. Minimum SDK is 24 because v2-only APK signing starts with Android 7.0. See the [Android v2 signing specification](https://source.android.com/docs/security/features/apksigning/v2).

## Commands and build artifacts

| Command | Purpose |
| --- | --- |
| `anpyra init DIRECTORY` | Create source and configuration in a new or empty directory |
| `anpyra check [PROJECT]` | Validate source and generate DEX in memory; write no artifacts or keys |
| `anpyra build [PROJECT]` | Compile, package, sign, verify, and write artifacts |
| `anpyra verify APK [--json]` | Verify Anpyra APK signature, content digest, DEX SHA-1, and Adler-32 |
| `anpyra doctor` | Show build prerequisites and optional adb availability |
| `anpyra install APK [--serial ID] [--launch]` | Verify and install through adb |

`build` and `check` accept `--dump-ir` and `--dump-dalvik`. The default project is the current directory. You can pass either a project directory or its configuration file.

Build output includes:

- `PACKAGE.apk`: signed, verified application.
- `unsigned.apk`: the package before signing.
- `classes.dex`: the generated bytecode.
- `AndroidManifest.xml`: binary Android XML.
- `build-report.json`: source/output paths, metadata, APK and certificate SHA-256 fingerprints, verification results, register maps, and method listings.

A build is verified in a temporary directory before existing output files are replaced. Each file replacement is atomic; replacing the complete artifact set is not a single transaction. Identical inputs using the same signing identity and tool versions produce identical APK bytes through fixed ZIP metadata.

One debug signing identity is retained in the project's `.anpyra/` directory, allowing rebuilt APKs to update the same installed package. Keep this directory private and backed up if you need that identity; `.gitignore` excludes it. An incomplete or mismatched identity causes an error instead of silently generating a replacement. Release signing, key rotation, AAB output, and store publishing are not implemented in v0.1.

## Use the build API

```python
from anpyra import build_project

result = build_project("myapp")
print(result.apk_path)
print(result.verification.v2_signature_ok)
```

Use `build_apk(source_path, out_dir, package=..., label=...)` for a single source file without project configuration. It also accepts `version_code`, `version_name`, `min_sdk`, `target_sdk`, and `state_dir`. Use `compile_source()` or `compile_file()` for AST and IR inspection. `CompileError` and `ConfigError` provide readable diagnostics.

## Supported Python

| Feature | v0.1 support |
| --- | --- |
| Application | One class extending `Activity`, one `on_create(self, state)` |
| UI | `TextView(self)`, `set_text(str)`, `self.set_content_view(view)` |
| Locals | Initialized `str`, `int`, and `bool` annotations; one declaration per name |
| Integer values | Names, signed 16-bit literals, simple `+` / `-` expressions |
| Conditions | Boolean variables; one integer comparison using `==`, `!=`, `<`, `<=`, `>`, `>=` |
| Branches | `if`, `else`, nested `if`, and `elif`; method calls and `pass` in branches |
| Helpers | Top-level typed functions with 0–5 positional `int` parameters and `-> int` |
| Helper bodies | One return of an integer name/literal or simple `+` / `-` expression |
| Helper calls | An initialized `int` assignment in `on_create` |

`set_content_view` must be called exactly once outside branches. Locals plus compiler temporary values in `on_create` are limited to 14 registers. Integer arithmetic uses Dalvik signed 32-bit behavior, including overflow. Locals cannot be reassigned. Compound expressions, arbitrary imports, extra classes/methods, decorators, loops, collections, callbacks, exceptions, general Python libraries, and CPython execution are unsupported. Unsupported constructs fail with diagnostics.

## Migrate your experiments

For an experiment 005–008 app, copy its `app.py` into a new Anpyra project and set the intended package in `anpyra.toml`. Existing `from pyandroid import Activity, TextView` source remains accepted through a compatibility package. New code should import from `anpyra`.

To update an already installed experiment app, preserve both its original package ID and signing identity. The experimental files `.pyandroid/debug-key.pem` and `.pyandroid/debug-cert.der` can be copied as a pair into the new project's `.anpyra/` directory. Otherwise use a new package ID or uninstall the old development app. No archived signing keys are included in this repository.

Experiments 001–004C are low-level milestones rather than source applications; their DEX, manifest, packaging, and signing work is represented by the framework's backend. See [architecture](docs/architecture.md) and the [roadmap](docs/roadmap.md).

## Development

```powershell
python -m pip install -e ".[dev]"
python -m unittest discover -s tests -v
ruff check src tests examples
ruff format --check src tests examples
python -m pip wheel --no-deps . --wheel-dir dist
```

Tests cover experiment 005–008 source compatibility, emitted DEX method instructions and branch destinations, configuration, CLI workflows, signing identity reuse, tamper detection, and reproducible rebuilds. CI runs on Windows and Linux with Python 3.11 and 3.13. Local binary verification is separate from real-device acceptance: install both examples on your Android phone before treating a framework release as device-validated.
